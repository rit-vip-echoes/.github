# **Playtest Preparation Guidelines**

## Creating a new Release

Before each playtest, teams must create and deploy a new build following the [deployment guide](https://github.com/rit-vip-echoes/.github/blob/main/profile/webGLBuild.md). This build should be to the main branch, not the dev branch!

Afterwards, leads must create a new Release in GitHub.

1. In the new release screen, create a new Tag and name it (semester number)-s(sprint number).
    -  Example: 2261-s2
2. In the release title field, name it (season) (year) - Sprint (sprint number).
    -  Example: Fall 2026 - Sprint 2
3. Make sure the target branch for the release is "main", not "dev"!
4. Use the "Generate Release Notes" feature. This creates a list of all changes since the last release, linking the appropriate PR and users in an organized list. It additionally highlights new contributors and links to a full change log since the last release.
5. Above where the release notes are generated, write a Release Overview. This should include a summary (written by you) of the changes since the previous release, including any known bugs.

See [this release](https://github.com/rit-vip-echoes/Dream-Swimmer/releases/tag/Summer2026) as an example.
